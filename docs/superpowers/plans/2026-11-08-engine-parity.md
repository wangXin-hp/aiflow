# 工作流引擎能力对齐计划

**目标：** 独立实现参考项目所具备的开始、结束、模型、HTTP、意图分支、知识检索、变量和运行记录能力，并保留已实现的布尔分支和 V1/V2 兼容。

**分层：** contracts 定义版本化协议；graph 负责图校验和拓扑；bindings 负责变量解析；nodes 负责节点注册与业务节点；adapters 封装模型、HTTP、检索；runtime 负责状态、事件、超时、取消和结果。核心不依赖 NestJS 或 React。

**范围与顺序：**

1. 将现有调度器按职责分层，保持现有测试与公开 API 不变。
2. 扩展协议与分支端口，增加 LLM、HTTP、意图分流和知识检索节点，提供可注入适配器及清晰错误；保留布尔条件。
3. 独立实现模型和检索基础设施，使用可控替身覆盖节点参数、成功、失败、超时、取消与多分支汇合。真实外部服务测试需可选且明确环境依赖。
4. 补齐输入/输出、运行事件、耗时与日志安全约束，编写从定义到执行的中文讲解和面试材料。
5. 逐项核对参考能力，运行所有测试、质量检查和构建；明确没有实现或没有外部环境验证的部分。

**约束：** 不复制参考项目源码；不把凭据或提示内容写入默认事件；请求支持 AbortSignal；保持协议向后兼容并对非预期类型明确报错。
