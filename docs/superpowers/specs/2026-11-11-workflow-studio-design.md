# AIFlow 工作流工作台与编辑器设计

状态：待确认  
日期：2026-11-11

## 目标与范围

面向已登录用户，交付从工作流列表创建流程、进入画布编辑、保存草稿、启动调试到观察节点结果的第一个前端闭环。工作流编辑器是项目的核心展示页面，要能向面试官直观说明图协议、乐观锁、固定运行快照与可补发事件如何协作。

本阶段实现列表、创建、归档、画布编排、节点配置、保存、单次调试和运行详情。发布/API Key、知识库管理、运行历史列表以及复杂移动端编辑留到对应后端能力与产品阶段；不能把未实现的发布功能放成可点击的假按钮。

## 已有约束

- 前端 React 19/Vite/TypeScript，后端 NestJS 11/PostgreSQL/Prisma；复用 `@aiflow/contracts` 的 V2 图、工作流和运行响应契约。
- 后端已提供工作流 CRUD、草稿运行、详情、取消及 SSE；还没有运行历史列表接口。
- 创建与保存会由服务端做完整图校验，因此新工作流使用可执行的 `start → end` 模板；编辑中的不完整图保留在内存并展示校验失败，不悄悄丢弃。
- 保存必须携带 `revision`。409 时停止自动覆盖，提示用户重新载入服务器版本；不自动合并或重试。
- 后端事件以持久化十进制 ID 为游标。前端只展示安全事件元数据；节点输入输出从受保护的运行详情读取。
- 使用 AIFlow 名称和独立实现的图标、代码、样式；参考项目源码标注不可开源，只参照通用页面区域、视觉层级与交互方式。
- 公共接口、核心流程及非显然约束添加简洁中文说明注释；保持现有格式、类型、检查、测试与提交门禁。

## 方案与取舍

1. **采用独立 React 画布状态与图协议映射，使用 `@xyflow/react` 负责交互。** 画布库提供平移、缩放、拖拽、连接和视图控制；业务图仍以 V2 协议为唯一保存格式。首期需要写清节点/端口映射，但能满足编辑器交互与参考视觉。
2. 使用原生 SVG 自建画布。依赖少，但拖拽、连线、缩放、命中测试和无障碍行为都需重做，个人开发周期不合适。
3. 直接迁移参考编辑器组件。视觉更快接近，但其源码许可不允许开源，而且数据协议、Next.js 布局与本项目不一致，不采用。

## 页面与交互

`/apps` 为工作流工作台：固定导航、标题、创建入口、按创建时间排序的工作流卡片、加载/空态/错误态、继续加载和归档确认。创建后立即进入 `/workflows/:id`。列表使用现有不透明游标，不自行猜测下一页；排序沿用服务端当前协议，避免分页错序。

编辑器采用全屏工作区：顶部 AIFlow 标识、返回入口、工作流名称、保存状态及“保存”“测试运行”；左侧约 208px 节点库；中间浅灰点阵画布和缩放/小地图控件；右侧约 400px 节点配置面板，调试时切换为约 420px 的输入、结果、追踪面板。卡片为白底、圆角、细边框、轻阴影，节点类型使用独立配色。参考页面的布局、间距与交互状态作为同视口并排截图的验收基准，不使用其商标、图标或素材。

首期可添加 `transform`、`condition`、`llm`、`http`、`knowledge`、`intent` 节点，`start` 和 `end` 从模板产生。新增节点带协议合法的最小配置；由配置面板完善必填字段。节点可移动、选中、删除、连线；删除节点同步清除关联边。唯一开始节点与结束节点不能删除或重复添加。连接端口按 V2 协议约束；无效连接即时反馈。保存前校验结构，后端作为图语义最终裁决者。布局和编辑命令与 React 视图分离，便于测试。

节点配置面板按类型呈现常用字段，变量绑定先支持字面量与上游输出引用，复杂模板以结构化编辑控件逐步补充。避免用原始 JSON 文本框作为主要交互；对暂未提供完整表单的高级字段可提供明确标识的高级 JSON 编辑区，并在保存前通过共享 schema 解析。

调试输入由开始节点 `config.inputs` 生成。点击运行时如有未保存修改，先保存并等待成功，再创建运行；保存冲突或失败时不启动旧版本，以免调试结果与画布不一致。运行创建后打开事件流，按节点状态更新画布；终态或刷新后通过 `GET /api/runs/:id` 读取最终结果。原生 EventSource 自动重连时发送最后事件 ID，页面显示重连状态；取消按钮调用取消 API。单次调试的最近运行 ID 保留在当前页面 URL 查询参数，刷新可恢复该运行详情，但不冒充完整历史记录。

## 数据和错误语义

客户端 API 层统一校验成功包装和错误包装，`credentials: include`。草稿状态保存服务端 `revision`、本地图、是否有未保存修改、是否正在保存。服务端返回的新 revision 才表示保存成功。网络故障保留未保存状态；离开页面时提醒，避免误丢编辑。新保存请求不能与旧请求并发覆盖；用户连续编辑时保存完成后仍保持未保存状态，直到所有本地更改被对应版本覆盖。

工作流列表的 401 使用现有认证状态处理。资源 404 显示可返回列表的错误页；400 图错误显示可定位的问题；409 冲突显示重新载入操作；5xx/网络错误允许重试。SSE 事件不可当作运行详情的唯一事实来源，终态和重连后均查询详情。

## 验收与验证

- 登录后创建模板工作流，移动/连接/配置节点并保存；刷新后图与名称保持一致。
- 另一会话更新草稿后，本会话保存收到 409 且本地改动未丢失。
- 输入合法的 `start → end` 图调试，页面显示运行和节点终态、输出与事件追踪；断线重连没有遗漏和重复展示。
- 画布以 1440×900 桌面视口和同一 `start → llm → end` 示例图对照参考页面截图，检查区域、卡片、面板、端口、缩放控件及选中/运行状态；记录可访问性和协议导致的差异。参考仓库只有源码、尚无可复现截图，截图验收需在获得参考画面后完成。
- 自动测试覆盖 API 契约错误、图编辑命令、保存冲突、调试终态与 SSE 重连；运行格式、lint、类型、构建和完整测试。真实豆包调用单独作为可选的付费冒烟测试，不作为 CI 门禁。
