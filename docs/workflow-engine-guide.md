# 工作流引擎：阅读与面试讲解

## 一句话定位

引擎把版本化的节点与连线定义校验为有向无环图，再根据依赖顺序逐个执行节点，通过变量绑定传递数据，记录节点状态，并将模型、HTTP 和知识检索封装为可替换适配器。当前实现是单进程、串行、内存执行。

## 跑一遍离线示例

在仓库根目录执行：

```sh
pnpm build
pnpm --filter @aiflow/workflow-engine demo
```

示例使用固定模型响应，不访问外部服务。阅读 `packages/workflow-engine/examples/intent-demo.mjs`，观察 sales 分支成功、support 分支跳过，以及结束节点如何用 `fallback` 处理未执行分支的输出。把固定意图改成 support 再运行，可以对比两条路径。

## 一次请求经过哪些层

```text
工作流 JSON + 输入
  → contracts/workflow-v2：结构与节点配置校验
  → v2/graph：端口、拓扑、可达性、引用校验
  → v2.ts：按拓扑顺序调度，决议各条边的执行状态
  → v2/bindings：从上游输出解析节点输入
  → v2/nodes：选择节点执行器并调用适配器
  → v2/invoke：超时和取消控制
  → 结果与事件：节点输出、状态、耗时、结构化错误
```

参考代码：[协议](../packages/contracts/src/workflow-v2.ts)、[图校验](../packages/workflow-engine/src/v2/graph.ts)、[调度](../packages/workflow-engine/src/v2.ts)、[节点](../packages/workflow-engine/src/v2/nodes.ts)、[变量](../packages/workflow-engine/src/v2/bindings.ts)、[服务适配器](../packages/workflow-engine/src/adapters)。

## 用分支汇合理解调度

开始节点输出输入数据；意图节点从模型响应中选择一个意图端口，其他意图边标记为 skipped。一个节点的所有入边决议后：全部 skipped 则节点跳过并继续传播，否则执行。汇合节点可以使用上游的安全引用；如果引用来自可能被跳过的分支，必须配置 `fallback`。当前引用可达性采用保守的支配关系检查，并不等于通用静态数据流分析。

## 调试及失败

节点开始后生成时间记录；正常完成时保存输出，错误时记录错误代码，后续未执行节点跳过。取消或超时只让引擎停止等待并通知节点，不能撤销外部副作用，也无法打断阻塞事件循环的同步代码。节点输入字段默认不记录，调试时可开启 `captureInputs`；节点输出仍会记录，尤其开始节点输出包含原始输入。持久化或展示前必须由应用层做脱敏和权限控制，不能把关闭输入捕获当作脱敏。

## 问答练习

- **为什么使用 DAG？** 可以在执行前检测环、确定依赖顺序，并解释某节点为何可以执行；目前不支持循环。
- **怎样避免分支汇合被错误跳过？** 用边状态决议入边，而不是把未选分支的所有后继无条件删除；测试同时验证 true/false 两条路径。
- **为什么要有适配器？** 调度器只依赖模型、HTTP、检索接口，测试可以注入可控替身；火山方舟豆包和 Qdrant 适配器负责外部协议。
- **如何处理超时与重试？** 当前支持节点超时和取消，不自动重试，也不承诺回滚；有副作用的操作需要幂等和独立的失败策略。
- **如何证明可靠？** 引用图校验、分支汇合、超时/取消竞态、服务响应和检索融合测试；只描述本地实际执行过的验证，不把替身测试说成真实服务联调。

## 功能边界

目前不含队列、运行持久化、断点恢复、用户代码沙箱和自动重试；条件意图响应要求严格 JSON。HTTP 网络策略由部署方配置，Qdrant 全文扫描受到数量限制。云端供应商和 Qdrant 尚未使用真实凭据联调。文本和 Markdown 基础切分、Qdrant 集合检查/创建、向量写入及文档删除已有实现；文档更新尚无原子替换，二进制 HTTP 请求体仍未实现；本项目不复制其源码或许可文本。

## 知识检索与日志的阅读顺序

1. 从 `knowledge/chunking.ts` 看文本、Markdown 分块和来源偏移；
2. 从 `knowledge/index-document.ts` 看依次向量化及一次写入，注意重新索引不会清理旧尾块；
3. 从 `knowledge/store.ts` 看稳定点 ID、维度校验及知识库范围内删除；
4. 从 `adapters/qdrant.ts` 和 `adapters/knowledge.ts` 看向量、全文扫描和排名融合；
5. 从 `v2.ts` 看日志如何随节点状态变化产生，注意日志与可能包含业务数据的运行结果是两类数据。

模拟端到端测试见 `knowledge.test.ts`；该测试的数据库与向量服务是替身，不能当作真实 Qdrant 或豆包向量服务联调成果。
